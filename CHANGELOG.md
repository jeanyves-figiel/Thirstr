- **Console Places page works again** (server, #323, A-07b): `/admin/places` returned an error once an OpenStreetMap import or an upcoming party existed. Raw `timestamp` columns come back as `NaiveDateTime`, and the page used `DateTime.to_iso8601`. Times are now formatted from both shapes. The page uses the v3 cards, and Delete asks inline instead of showing a browser dialog.
- **Promote can pull the staging image again** (ops, #168, EN-09): since the move to org `thirstr` the production `FLY_TOKEN` held only prod app tokens, so canary and rollback updates failed with "Not authorized to access this imageref" for `registry.fly.io/thirstr-api-staging@…` (promote run 24; prod stayed on the old image, passkeys migration already applied, expand-only). `fly-ci-tokens.sh production` now also mints a `thirstr-api-staging` deploy token.

- **Edit profile usable again with a main photo** (app, #305, S-74): the main photo tile grew to the full screen height on iPhone, pushing quick wins and every section row off screen. - **Org move script** (ops, #168, EN-09): `scripts/ops/fly-org-move.sh <staging|prod>` moves one environment's Fly apps to the org `thirstr` in the safe order (stop API, move DB/Valkey/classifier/bot, new private classifier address, move + start API, smoke). - **Verification needs the genuine app on a real phone** (server + app, pen test #270, F-03): the server no longer trusts a "passed" liveness result on its own. On staging and prod a pass must come with proof from the calling phone over that exact request (`"<nonce>.<blinded>"`): an App Attest assertion with the attested key (iPhone) or a Play Integrity token (Android). Without it: no credential (`attestation_required`). At most 3 credentials per phone per day. Scripted clients can no longer mass-verify fake accounts. `VERIFICATION_REQUIRE_ATTEST` enables it (on by default for staging/prod); the EN-13 flag `verification_attest` turns it off at runtime without a deploy.
- **Play Integrity on Android** (server + app, #168): daily Google Play verdict bound to a single-use server challenge (genuine Play app, device integrity, package, ≤ 5 min, optional signing cert). Server decodes with a service account (`PLAY_INTEGRITY_SERVICE_ACCOUNT_JSON`); app needs `EXPO_PUBLIC_PLAY_CLOUD_PROJECT_NUMBER`. Off until both are set (setup: `docs/runbooks/cert-pinning.md`).
- **Certificate pinning** (app, #168): the API hosts are pinned to CA keys (Let's Encrypt X1/X2 and the new Gen Y roots YR/YE, backup Google Trust Services R1/R4), never to our renewing leaf: iOS `NSPinnedDomains`, Android network security config with an expiry date so it can't brick old builds. A machine-in-the-middle proxy with its own CA can no longer read or script the app's API traffic. Runbook `docs/runbooks/cert-pinning.md`.
- **Chat and album media only for the people it was sent to** (server + app + test bot, #271 pen test, F-08 R-08.18, AC-08.9): photos, videos and album items are now tied on the server to the accounts a message carrying them was delivered to. Anyone else gets "not found" even with the id, and download links expire after 15 min instead of up to 12 h. Media from older app builds keeps working until it expires.
