Screens checked with an automated overlap scan on 320, 375 and 393 pt wide phones in en / fr / de.

The menu now closes first and the share sheet opens once it is gone.
- **App kept signing you out / chat always "Waiting for network"** (#116, R-01.5): after 15 min idle the access token expires and several requests refreshed it at the same time with the same refresh token. The server saw the second use as a stolen token and deleted the device (sign-in, chat keys and pending messages gone), so the app signed out and realtime was refused. The app now refreshes once and shares the result, and signs out only on a definitive 401/403 (not offline, 409, 5xx). Server: re-use of a refresh token spent less than 60 s ago returns 409 `refresh_race` without revoking; older re-use still revokes the device. Concurrent refresh no longer crashes with a 500.
- **Map now opens on your position** (#95, R-04.13): the Explore map stayed zoomed out on the world because it only read the position when it first appeared, before the phone had a fix. It now centres on your own position as soon as it is known (whatever your location level: Hidden, City, Area or Exact), asks for location access once if never asked, and keeps the map where you put it if you already moved it. New "Locate me" button recentres. Your exact position never leaves the phone. `GET /me` returns your own coarse cell (`location.cell_r5`) so City users without location access start on their city.
- **iPhone app stuck on launch** (#90): startup waited forever when reading the saved sign-in from the keychain or reaching the server failed or hung. Each startup step now has a time limit and falls through to the Welcome screen. A failed check no longer signs you out unless the server rejects the session.
- **iPhone app still opened to an empty screen** (#88): the screen frame waited for the phone to report its safe-area insets before drawing anything. It now starts from known measurements. Errors during startup are shown on screen instead of nothing. `expo-asset` (needed by fonts) is now a direct dependency.
- **Chat works on bad networks** (app, #76, #79): every outgoing message, reaction and receipt goes to an encrypted on-device outbox before sending and is retried automatically (1 s → 60 s backoff), also after the app is killed. Reconnect, launch and foreground send at once. Gives up after 24 h with "Not sent. Tap to retry." (same message, never a duplicate). Requests time out (15 s send, 10 s pull/ack) and the chat header shows "Waiting for network" when the connection is down.
- **No duplicates on retry** (app, #78): the message is encrypted once; retries resend the same ciphertext with `client_id`.
- **No silently lost messages** (app, #80): a message that can't be decrypted yet is kept up to 24 h and retried after each welcome/commit (e.g. it arrived before its chat setup); then a "couldn't be decrypted" notice is shown and the 1:1 chat re-syncs its keys. Messages expired on the server while away show a notice with the count. Pull acks only after everything is saved; re-deliveries after a kill aren't processed twice.
- **Chats keep all messages** (app, #81): one encrypted row per message instead of one blob capped at 500; writes to a chat are serialized so a send and a receive at the same time can't overwrite each other. Existing chats migrate on first open. Messages sort by sender time clamped to server time.
- **Chat send can't duplicate or half-deliver** (server, #78): `POST /mls/messages` takes `client_id`; a repeat from the same device within 7 d returns the first result and stores/pushes nothing. All envelopes of one call are stored in one transaction (all-or-nothing); `message.new` goes out after commit.
