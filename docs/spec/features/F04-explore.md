# F-04 Explore: map, grid, modes, filters

## Purpose
Home tab. See who's around now, fastest path to a message.

## Layout (S-10 map, S-11 grid)
Top (#113, option B of the [merged map mockup](https://claude.ai/artifact/JiM6adMvw99ZAng34Vov2i)): the map is **full-bleed** under a **floating glass header** (R-04.18): one bar with wordmark · place + level + live counts (tap → S-30) · Filters · own avatar (Now), and under it the **intent chips** Hookup · Friends · Sport (multi-select). Body (#100, concept A of the [blend mockup](https://claude.ai/artifact/J74uiYDyi1vJ9URjttLke9)): one map for everyone, each person ringed in the colours of what he's looking for (R-04.19), place markers (R-04.20), and a pull-up **grid sheet** over it (R-04.14) with the **place chips** Clubs · Saunas · Parties · Gyms just above it. There is no Map/Grid toggle: the sheet's full state is the grid. Tab bar: Explore · Tonight · Chats · Me.

## Rules
- R-04.1 (Explore superseded by R-04.18 for the map and grid; still applies to Tonight, profile view and other mode screens.) Mode is the viewer's lens (F-06 R-06.1a/b): it shows profiles whose `show_in` includes the mode, rendered through that lens, and recolours UI (mode tokens, design-system). Mode persists across launches. Switching mode never changes the viewer's own profile. If the viewer isn't shown in the current mode: one-line banner "You're not shown in Friends · Show me" (turns it on; Sport runs the mini-setup first).
- R-04.2 Map: MapLibre, dark style. Shows (a) for viewers who get counts only (R-04.10), a count bubble at each cell centre (no cell shapes: hex zones removed in #223, they read as confusing areas and showed exact cell edges), (b) avatars of Area users placed at random stable positions inside their cell (seed = profile_id + day), (c) exact pins for Exact users the viewer is allowed to see (F-05), (d) place markers: venues, official and hosted parties (R-04.20). Every cell that touches the viewport is included (the box is padded by about one cell edge before it is filled), so zooming in inside one cell still shows its counts and people.
- R-04.3 Pins: avatar 36 px, intent ring (R-04.19); "door open"/"hosting" badge; countdown ring for TTL; pulse animation for Now status posted < 10 min ago (reduced-motion: static).
- R-04.4 Sort (grid sheet and `GET /explore/tray`), #197: **nearest first, always**, by the distance shown on the card (R-04.6, rounded), then Now, then online recency. Exact pins and Now no longer jump ahead. City-only people (no number) come last under an "In {city}" label. `further` people (R-04.7) stay after near ones. The horizontal tray is replaced by the grid sheet (#100); `GET /explore/tray` stays for the sheet title count ("Active now · N").
- R-04.5 Grid (inside the sheet, R-04.14): 4 columns by default, 2–4 by pinch or Filters (F-19 G8, #223), card = main photo, name, verified tick, online dot, distance bucket, Now/Exact badge. Infinite scroll, page 60. Same sort as tray. Later pages follow the order computed for page 1 (kept 2 min, per viewer, location and filters; blocks and hides re-checked per page); page 1 and pull-to-refresh always recompute (SR-09). No paywall, no cap.
- R-04.6 Distances (#197): a real rounded number, step set by the shown person's precision (R-05.15, rounded down):
  | Precision | < 1 km | 1–10 km | ≥ 10 km |
  |---|---|---|---|
  | Exact pin | 10 m ("40 m") | 0.1 km ("1.3 km") | 1 km |
  | Precise r10 | 50 m ("~150 m"), floor "< 100 m" | 0.1 km ("~1.3 km") | 1 km ("~14 km") |
  | Area r9 | 100 m ("~400 m"), floor "< 200 m" | 0.5 km ("~1.5 km") | 1 km |
  | Area r8 / r7 (widened) | "< 1 km" | 0.5 km (r8) / 1 km (r7) | 1 km |
  | City | "In {city}" | | |
  Exact shows no "~"; Precise and Area show "~". Unverified viewers: never under "~1 km" (R-04.10). Owner setting `show_distance` (S-67): `exact` (default since #197, shown as "Number") = these numbers; `range` = legacy buckets only; `none` = no distance. Spoof brake (R-05.16) also gives legacy buckets "< 200 m", "200–500 m", "500 m–1 km", "1–2 km", "2–5 km", "5–10 km", "10+ km". Grid card marks precision: coral dot = Exact pin, teal dot = Precise, none = Area.
- R-04.7 Sparse areas: if < 30 profiles within 10 km, grid widens radius automatically up to 100 km and labels section "Further away".
- R-04.8 Filters sheet (all free): age range; distance max; verified only (default on); online now; has Now status; position (hookup, verified viewers only); hosting; tribes; body; looking for; Sport: sports, level, schedule, intent; hide creators (default on); new members only. Saved per mode. Never filterable: HIV status, ethnicity, languages (#106: chats translate on device instead, F-07 R-07.25).
- R-04.9 Viewer filtering server-side: never return blocked (both ways), paused, quarantined (to others), Hidden users; respect `hide_from_hidden` when viewer is Hidden; respect profile `visibility_map` for card fields.
- R-04.10 Unverified viewer: sees cards and buckets ≥ "1–2 km" only, no pins; tapping message shows verify prompt.
- R-04.11 Performance: first grid paint < 300 ms p95 (cached last result shown instantly, refreshed in background); map tiles cached offline for last city.
- R-04.12 Pull-to-refresh on grid; map updates live via `cell:{r7}` channel.
- R-04.13 Map centring (#95). The map opens centred on the viewer's own device position at start zoom (12), whatever their location level (Hidden / City / Area / Exact): how others see you never changes what you see. The raw position stays on the device; only cells are sent (R-05.1). Order: (1) device GPS (last known fix first for an instant start, then a fresh fix), (2) own Exact pin, (3) last sent area cell, (4) own stored cell (`location.cell_r5` from `GET /me`, City users without permission), (5) world view. When Explore opens and permission was never asked, ask once (iOS "When in use"). The map auto-centres once, when the first usable position arrives, unless the user has already panned or zoomed. Start zoom follows R-04.15 (auto-fit) once `fit_m` is known, else 12. A "Locate me" button (44 px, round, white, bottom-right just above the sheet, moves with it) recentres with a 600 ms ease; if permission is off it opens the Location sheet. The own dot is drawn at the device position (falls back to the centre above).
- R-04.14 Grid sheet (#100). A bottom sheet over the map holds the grid (R-04.5). **Two stops** (#250, option B of the [two-stops mockup](https://claude.ai/artifact/4otVv3QabTP8n5jcsFcVwH); was peek/half/full), measured from the bottom of the screen area above the tab bar: **strip** (default: handle, title row and the Moments row with You first, 164 pt; the map fills the rest) and **full** (up to just below the header; the map is hidden). Both stops hold the **same list**: Moments row (F-21), the one-time hold hint, then the grid; the strip just shows its top. Drag the handle or the title row to move it (spring, `motion.slow`); release snaps to the nearest stop or, on a fling, the other one; tapping the handle toggles. Last stop is remembered per device (a saved `half` opens as the strip). In full the grid scrolls (infinite scroll, pull-to-refresh); in the strip the list scrolls inside the visible part. Tapping the visitors bubble opens full. Title row: "Active now · N" (N = tray count, real) or "Nearby" when N = 0, right side "Nearest first". The Locate me button and the zoom note ride 12 pt above the sheet edge. Reduce Motion: snaps without spring.
  - Pin ↔ tile: tapping a map pin selects it: the pin grows 44 → 58 px with a coral ring and a white name chip "Name, age · distance" below; its tile in the sheet gets a 3 px mode-colour ring and the sheet scrolls it into view (half if it was peek). Tapping the chip or the tile opens S-20. Tapping the map elsewhere clears the selection. Long-press on a tile keeps quick actions.
  - Map camera padding: the map's visible centre is the part above the sheet, so centring and auto-fit keep the viewer's dot and nearest people above the sheet.
- R-04.15 Auto-fit zoom (#100). `GET /explore/grid` returns `fit_m`: the radius reaching the 12th nearest visible person (or the furthest, if fewer), rounded **up** to one of 500, 1 000, 2 000, 5 000, 10 000, 25 000, 50 000, 100 000 m; at least 2 000 for unverified viewers (R-04.10); `null` when nobody is visible. On the first centring and on each Locate me, the client sets zoom so a circle of `fit_m` around the viewer fits the map area above the sheet (zoom clamped 9–15; `null` → 12). A small chip above the sheet says why: "Fitted to your nearest people" or, when `fit_m` ≥ 5 000, "Zoomed out to reach people". The rounding means `fit_m` never tells more than the distance buckets already shown.
- R-04.16 Quiet area and empty states (#100). Never show invented counts or filler profiles.
  - Quiet: nobody within 2 km (first grid card is `further` or its bucket ≥ 2–5 km) and at least one card: sheet title "Quiet right here", sub "Nobody active within 2 km yet. Here's who's further out."; a "Be the first one here" card (Post a Now → Now sheet; unverified → Verify) ; then the grid under a "Further away" label; then, if `GET /tonight` returns plans, one row "Tonight near you · N plans" → Tonight tab.
  - Unverified viewer with no cards: sheet shows a teal card "Verify to see who's here. Most guys only show to verified members." → Verify. The map keeps count bubbles only (R-04.10).
  - Nobody at all (verified, 100 km): existing empty state (title "Nobody visible here yet", Filters action) inside the sheet, plus the Post a Now card.
- R-04.17 Live header (#104). Replaces the static top bar. **Superseded on Explore by R-04.18 (#113)**: rows 1–2 become the floating bar, row 3 mode tiles and the glow are removed (intent chips instead). Counts, place name and banner rules below still apply.
  - Row 1: wordmark (left). Filters button (44 pt round `bg.raised`, badge = number of filters that differ from the defaults, hidden at 0). Own avatar button (44 pt; main photo or initials): ring dashed in the mode colour when the viewer has no Now status, solid when Now is on; tap → Now sheet (F-09).
  - Row 2 (one button, tap → Location sheet S-30): place name as a 30 pt headline + chevron. Place = name of the nearest city (`cities` table) to the viewer's own query cell, never a finer place; "Somewhere" when unknown. Under it: teal level chip (pin icon + "Area · ~200 m", "City", "Exact" or "Hidden"), a mode-colour live dot, then "**N** around · **M** Now" (Sport: "**N** around" only, no Now in Sport).
  - Row 3: three equal mode tiles (74 pt, radius 20): icon (flame / two people / dumbbell), count top-right, label bottom. Active tile filled with the mode colour, ink text, soft coloured shadow; inactive `bg.raised` with the icon on a mode-tinted disc. Tap switches mode (same as the old segmented control, `tablist` semantics).
  - Behind the header, a soft radial glow of the active mode colour (22 % alpha) fades into ink; it cross-fades on mode switch (Reduce Motion: instant).
  - Counts come from `GET /explore/summary` (api.md): N = people the viewer can see in that mode within 10 km (same visibility rules as the grid, R-04.9, R-04.10); active mode with the viewer's filters, other modes with default filters; M = those with an active Now status. Shown as is up to 99, then "99+". No count yet / error: the number slot shows "·" (never a made-up number). 0 is shown as 0.
  - Banners: the verify nudge leaves the header and becomes a slim teal row at the top of the grid sheet ("Verify to see faces and message first" + "Verify"). Missing main photo, "not shown in this mode" (R-04.1) and Safe Mode banners keep the slot under row 3, one at a time in that order.

- R-04.18 One map, intent chips (#113, option B). Explore no longer splits people by mode.
  - **Intent chips** under the floating bar: Hookup · Friends · Sport, each a 36 pt pill with a ring-shaped dot in its colour, label and count (R-04.17 N for that intent alone). Multi-select, all on by default; the last chip on can't be turned off. Saved on the device. `aria-pressed` per chip.
  - Map, grid sheet, tray and header counts show everyone whose `show_in` shares at least one selected intent (same visibility rules, R-04.9 / R-04.10). Header "**N** around" = that union; "**M** Now" = those with Now (no Now when Sport is the only chip).
  - Each card is rendered through one lens (F-06 R-06.1b): his first intent, in order Hookup → Friends → Sport, among the selected chips. Tapping opens the profile in that lens.
  - Filters: one saved set. Hookup-only filters (position, hosting) apply and show only when Hookup is the only chip; Sport filters (sports, level, schedule, intent) only when Sport is the only chip.
  - App mode (accent, tab bar, other tabs) = the first selected intent in order Hookup → Friends → Sport, so a single chip recolours like the old mode switch.
  - Floating bar: 56 pt, radius 28, ink at 82 % over the map, 1 px `line` border, soft shadow, 12 pt side inset under the safe area. Holds wordmark, place (headline 14) + teal level label + "N around · M Now" (meta), Filters (40 pt, badge), avatar (40 pt, Now ring). Banners (R-04.17) sit under the chips.
- R-04.19 Intent ring (#113). Every person pin shows his intents = `show_in` ∩ {hookup, friends, sport}, **all of them, whatever the chips**. One intent: full ring in that colour. Several: equal segments, clockwise from 12 o'clock, always Hookup (coral) → Friends (violet) → Sport (lime), 5 px gaps. Pin 52 pt (selected 60 pt), ring 4.5 pt, face 36 pt (40 pt). Now: 14 pt white dot top-right with ink border. Exact pin: 3 pt teal halo outside the ring. Grid tiles show the same intents as a 4 pt bar at the tile bottom (segments left → right). Screen-reader label: "Sam, 31, looking for Hookup and Friends, 400 m". `GET /explore/map|grid|tray` cards carry `intents` (ordered list). No data beyond his own `show_in` choice, which any lens already reveals.
- R-04.20 Place layers (#113). Place chips above the grid sheet (left of Locate me), toggles saved on the device (key `thirstr.exploreLayers.v2`, bumped in #223 so the new defaults reach every phone once): **Clubs** (club + bar), **Saunas**, **Parties** (official + hosted), **Gyms**. Default (#223) Parties on; Clubs and Saunas off; Gyms off, but on by itself while Sport is the only intent chip, until the viewer toggles Gyms once. Chip on = filled white (Parties yellow `personal`), ink text; off = solid raised ink `bgRaised` (#250: glass let map markers show through), `fgSecondary` text.
  - Markers: 34 pt rounded squares (radius 11, never circles, so they don't read as people), white with an ink stroke icon (note / steam / dumbbell); parties yellow with a sparkle and a small time tag ("TONIGHT 23:00", "22:00"). Drawn under people. Max 150 per view, nearest the map centre first.
  - Data: `GET /places?bbox&kinds` (api.md) from our own catalogue only (F-12 R-12.9, F-10 R-10.10). The client never calls a third-party place service; the request carries only the viewport, like map tiles.
  - Tap a marker → place card over the sheet: kind label, name, distance bucket, here line ("12 here", "A few here", none at 0; R-12.5 labels), buttons: venue → **Check in** (F-12 flow; the server still enforces ≤ 1.5 km) + **Directions** (the phone's maps app with the venue's public coordinates); official party → **Directions** + link if any; hosted party → **Request to join** (S-14). Footer "© OpenStreetMap contributors" for OSM venues. Tap the map or ✕ closes it.
  - Safe Mode viewer: no place layers, no chips (F-14). Unverified viewer: venues and official parties yes, hosted parties no (audience rules, F-10).

- R-04.21 Travel (#188, F-20): visitors to the viewer's area are interleaved into the grid with a sky outline and travel label (R-20.10), never pinned on the map (one "N visiting" bubble, R-20.11); Look around a trip city (R-20.14) sets the viewer point to that city's centre. Filters gain **Show visitors** (default on).
- R-04.22 Favorites / Friends only (#247, [mockup board A](https://claude.ai/artifact/333MUDiSEuQkEYKCM3RmDA)). A **people chip** after the intent chips: icon + chevron (36 pt): outline star while everyone is shown; filled sunflower with a filled star (Favorites) or violet with a person icon (Friends) while on, so the intent chips keep their labels. Tap → menu Everyone / Favorites (count) / Friends (count) + "Filtered on this phone. The server never sees your list." Choice saved on the device (`thirstr.exploreShow`).
  - Filtering happens on the phone only: the map keeps avatars and exact pins whose profile id is a favorite (R-07.32) or an accepted friend (R-07.34); anonymous count bubbles are hidden; the grid keeps the same people and loads further pages until 12 matches or the end of results. No new request parameter: the server sees the usual Explore request.
  - Sheet title "Favorites · N" / "Friends · N". Under the grid, **Not on the map right now · M**: favorites / friends missing from the results, with name + photo saved on the phone, "Not around right now" (never "hidden", never a location) and **Chat** (opens the 1:1 chat, else the profile).
  - Nobody matching and no more pages → empty state "No favorites around" / "No friends around".

## Edge cases
- No location permission → city level; map centred on chosen city (R-04.13 fallback 4); banner to enable.
- Offline → cached grid with "Offline" chip; actions queued.
- Viewer in Safe Mode → map shows only city-level counts, no pins, grid only verified.

## Acceptance criteria
- AC-04.1 3 taps max from cold start to compose a message to nearest person.
- AC-04.2 No API response contains another user's raw coordinates unless they're an Exact pin allowed for the viewer.
- AC-04.3 Hidden users never appear in any Explore response.
- AC-04.4 Mode switch recolours all surfaces incl. tab bar within 250 ms.
- AC-04.5 Fresh install, permission granted, any location level: Explore map shows the viewer's own position at zoom 12 within 3 s of opening, without user action.
- AC-04.6 Explore shows the map and the grid sheet together; no Map/Grid toggle. The sheet snaps peek/half/full and the last snap survives a restart.
- AC-04.7 With 12+ people within 1 km, the map opens at the zoom fitting `fit_m` = 1 000 m above the sheet, not at zoom 10/12.
- AC-04.8 Tapping a pin highlights the same person's tile; tapping the chip opens their profile (AC-04.1 still ≤ 3 taps).
- AC-04.9 Nobody within 2 km: "Quiet right here" + Further away; no number on screen that is not a real count.
- AC-04.10 Header counts match `GET /explore/summary` for each mode; a profile hidden from the viewer (blocked, hidden, hide-from-unverified…) is never counted; place name is city-level only.
- AC-04.11 (#113) With all chips on, a profile with `show_in` [friends, sport] appears once on the map with a two-segment violet/lime ring; with only Hookup on he is gone. Cards carry `intents` in order hookup → friends → sport.
- AC-04.12 (#113) `GET /places` returns only catalogue venues, official events and hosted parties allowed for the viewer; hosted parties only at their r8 centroid; Safe Mode → empty. No client request goes to a non-Thirstr host for places.
- AC-04.13 (#247) With Favorites on, the map and grid show only favorites returned by the normal Explore request, count bubbles are gone, and no Explore request carries any favorite or friend id. Favorites not returned are listed under the grid without a reason or location.
